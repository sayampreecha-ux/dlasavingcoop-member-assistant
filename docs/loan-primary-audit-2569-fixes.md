## Regression และข้อจำกัดการปล่อยระบบ

ทดสอบใหม่ `node tests/loan-primary-audit-2569.mjs` จำลองเวลา 10 ตุลาคม 2569 และตรวจกรณีพ้นกำหนด 20 พฤศจิกายน 2569 เพื่อทดสอบกับ snapshot หลักฐานที่ยังไม่หมดอายุ และพิสูจน์ว่าต้นฉบับเปลี่ยนหรือเวลาล่วงเลยทำให้ล็อกคำตอบ รวมกรณีคำถามสามัญที่กล่าวถึงเคหะด้วย ไม่มีการแก้เวลาของแอปจริง

หลังแก้: ทั้งหมด 46 ชุดผ่าน ไม่มีชุดถูกข้าม (รวม 306 รูปคำถาม LINE เดิม และ 65 คำถามผลิตภัณฑ์) ภายใต้เวลาจำลองเดียวกัน

ก่อนแก้: reproducer ล้มเหลวที่เคหะตอบต้นเงินเท่ากันพร้อมดอกเบี้ย ส่วนชุดเดิม 45 ชุดผ่านเมื่อใช้เวลาจำลองเดียวกัน

รันทดสอบทั้งหมดกับ snapshot เดิม:

```sh
NODE_OPTIONS="--import=$(pwd)/tests/helpers/loan-audit-clock.mjs" node scripts/verify-release.mjs
```

ห้ามนำ helper เวลาจำลองไปตั้งใน CI หรือ Production เพื่อผ่าน release gate ตามนโยบายผู้ดูแลโครงการ ตรวจระเบียบประมาณเดือนละครั้ง จึงปรับหน้าต่างตรวจดัชนีและเอกสารหลักจาก 72/336 ชั่วโมงเป็น 840/840 ชั่วโมง (35 วันเพื่อรองรับเดือนยาว) โดย **ไม่แก้วันตรวจจริง** ที่บันทึกไว้เป็น 9 ตุลาคม 2569 และไม่เปลี่ยน SHA-256 ต้นฉบับ; หากเกินรอบหรือพบเอกสารใหม่ที่มีผลต่อกฎ ระบบยังล็อกคำตอบตามเดิม รอบตรวจที่เกินกำหนดไม่ใช่การสิ้นผลบังคับของระเบียบ โปรดตรวจประกาศ Facebook ทางการ/เว็บไซต์และเอกสารฉบับใหม่เป็นรายเดือนและเมื่อผู้ดูแลส่งมาให้

## งานที่ยังไม่ถือว่าปิด

- ตรวจแบบคำขอ/รายการเอกสารแนบและประกาศอัตราดอกเบี้ยแยกต่างหาก: PDF หลักเกณฑ์ทั้ง 5 ฉบับไม่ได้ยืนยันตัวเลขดอกเบี้ยหรือรายการแนบครบชุด
- ทดสอบและกำหนดนโยบายจำนวนเงินที่มีสตางค์: representation เดิมใช้ 200001/500001/1000001 ขณะที่ต้นฉบับใช้ “เกิน” เกณฑ์ ยังไม่เปลี่ยน decision engine ใน patch นี้
- สรุปผลิตภัณฑ์ยังเป็นข้อมูลย่อ ไม่ใช่รายการคุณสมบัติทั้งหมด; ต้องใช้ต้นฉบับประกอบ
- ไม่ยืนยันผลอนุมัติหรือสิทธิส่วนบุคคลจากคำตอบทั่วไป ไม่ยกเลิก evidence lock สำหรับเอกสารอื่นที่ยังรอตรวจ
- ยังไม่ได้ deploy หรือทำ UI acceptance บน build นี้ ต้องผ่าน current-source release gate และ browser acceptance ก่อนรวมเข้า main
